# 术语与辅助视角

## 通用默认与项目术语

默认使用可观察描述，例如“组织内部推动 AI 应用的人”“组织人与 Agent 协作的实践”。本包不建立人物能力等级，不预设专有身份标签、缩写含义或个人成长层级。

若当前任务通过获准的 [项目上下文](project-context.md) 提供术语，记录术语、原定义、适用范围和版本；必要时保留原文，不自行扩写缩写或补足缺失层级。定义不清时只描述实践。配置可覆盖项目称呼，不能宣称它是行业标准、能力认证或已经证明的商业成功。

对外使用项目定义须同时有适用证据和披露许可。私人定义仅获内部许可时只在相应内部输出使用，不连同来源、私人原分或身份转交其他 Agent。当前请求与文档定义冲突时列明冲突；只处理依赖该定义的部分，其他通用评估继续。

## 写人物样本

先写问题如何定义，人和 Agent 各做什么，有何产物，如何判断质量、处理失败、积累系统与学习，再决定是否需要项目称呼。工具、付费档位、Skill 数量、Agent 数量、收入或年龄单项都不能证明能力等级。组织内部赋能也可有价值，不以独立收入作为必要条件。

## 辅助提问

- 组织角色：在创造可复用工具、方法并赋能同事，还是使用已有工具改善工作？两种角色都可有价值。
- 任务环境：能否沿用标准流程，是否需要专业分析、试探学习或紧急止损？
- 成长与学习：经验失效时怎样发现问题、接收反例和形成反馈？

这些只是提问视角，不对个人永久定级，不建立成长阶段与任务环境的一一映射，不引用未经测量的人群比例或成效倍数。

# industry-signal-editor

为 AI 产业内容提供研究与编辑判断：判断材料对谁有用、依据是否可靠、机制怎样迁移，并区分正式信号、案例研究、内部观察与排除。

定位源于 Randy 的“AI时代，我们如何安身立命？”与“AI＋大航海”：服务创业者、企业经营者、超级个体，以及希望理解变化、拓展边界的人。保留 AI先锋／OPT 的专门定义，不把它们当行业认证。

## 使用

向支持文件型技能的助手提供 [SKILL.md](SKILL.md)，连同本次材料、受众、用途、时间范围和已授权的来源。安装时应保留整个技能文件夹并命名为 `industry-signal-editor`，不要只复制入口文件而丢失 references。具体安装路径与自动发现方式取决于宿主；本目录没有执行安装，也没有验证自动加载。

可用请求：

- “评估这篇材料对中小企业采用 Agent 有何启发；标明实际读取范围与证据缺口。”
- “从这些候选中整理日报，去重，并分别列出正式信号与案例研究。”
- “这条内容收到反例后是否应改判？先核实新材料，说明改了什么。”

一次请求只授权编辑判断；账号读取、采集、联系、排程和发布须有各自的明确授权。本技能不自动执行这些动作。

## 评分与计数

编辑分为业务相关性30、实际影响25、证据质量20、可行动性15、时效性10之和。它是暂行编辑判断，不是客观测量、事实概率或经营收益预测。

| 区域 | 条件 | 计数 |
| --- | --- | --- |
| 正式信号 | 至少75分，核心事实已核实、启发明确，并满足本次用途与时间范围 | 计正式信号数 |
| 案例研究区 | 70–75分，有研究价值、来源可追溯、材料已读、机制有依据；待核结果与复用条件明确 | 单列案例研究数，不并入正式信号数 |
| 内部观察 | 低于70分，或证据、类型、许可、时间等不满足对外候选条件但仍有追踪价值 | 不计每日合格条数 |
| 排除 | 对受众没有可解释价值、没有追踪线索，或材料核心主张被否定 | 不计数 |

75分优先检查正式信号条件；达不到正式条件的案例，只有满足案例研究条件才进研究区。高分不免核验，不能把82分待核材料改成75分来进入研究区。69、63、64分均不能用“研究候选”等泛称混入计数。

本候选的默认计数约定：未另作约定时，“每日合格条数”指正式信号数；案例研究数另外报告。若任务明确要求包含案例研究的总数，也必须同时列出两项明细，排除内部观察、重复事件、未获准公开的材料与时间范围外内容。数量目标不授权降门槛、抬分或发布。

详见 [评分与分区](references/scoring-rubric.md)。

## 合成测试与验证限度

[synthetic-cases.json](tests/synthetic-cases.json) 含九项历史合成题的脱敏改写，以及六项新计数边界题；全部人物、组织、数字和日期均为虚构测试数据。案例中的“已核”只是假设前提，不能引用为真实事件。

运行 `python3 tests/check_fixtures.py` 可检查合成数据的分数加总、分区、计数与历史结果隔离；它只验证预期数据一致性，不执行模型或 Skill。

原九项测试由同一 Claude 会话按原 v0.3 实际写出输出，规则作者与执行者相同，非独立模型、非盲测，后四题由同一执行者自写。本包只保留其粗粒度历史结果，并给出当前候选的新预期；没有把改写后的预期冒充新一轮模型执行。T2/T4/T6 的69/63/64分原称“研究候选”，当前预期全部改为不计数的内部观察。T1 是74分战略内容，也不能冒充案例研究。T7 的74分具体案例在符合研究条件时改为案例研究区。

本地结构、链接、分数加总和计数一致性检查不证明编辑能力、真实商业效果或长期稳定性。没有验证运行时安装／自动加载；没有宣称 PyYAML 官方验证通过。评分档位与近似排序仍需在真实且获准的材料上校准。
